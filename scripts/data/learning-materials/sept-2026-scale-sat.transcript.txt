Deploy: `agents-cli create live-agent --adk` (Ankur). The manifest has the agent name, local path, Docker build folder, and region. Targets include Agent Runtime, GKE, and Cloud Run. The identity shows in IAM. Logs stream during deploy. Ankur asked how to get an agent created in Studio into the local repo. Copy the code (get code) into the repo and deploy with the CLI. Gemini Enterprise: Ian asked. Sonika: you can distribute the agent inside the organisation's existing Gemini chat, so you do not have to build a custom UI for that audience.

API: the lab was updated for curl and Postman. From the manifest folder, curl needs engine name, project number, token, and engine id. The identity URL is in the agent settings. A successful call returns the OpenAPI description. FastAPI: `main.py` outside the agent route wraps the agent as an API, including streaming for the agent engine. Hello GDG London asked; Sonika confirmed.

Nanjundan: several root agents in one repository. Deploy each one. Separate repos, or a script that changes directory so each manifest is used. One runtime deploy does not expose a switch between root agents. CI: build the container in GitLab so its scanners run, then deploy the artifact.

Sessions: the console records conversations, tool calls, and traces. Open them in the playground. Request and response body logging is optional for governance; Sonika had not turned it on. Traces have session, trace, and span views with timestamps and latency. In code, sessions are not automatic. Create a session service with project, location, and engine id and attach it. After that, refresh keeps the session. Add a new-chat control for a new thread. OpenTelemetry is on by default via an environment flag and can be disabled. Nanjundan asked whether a GCS/ADK runtime still needs a separate observability product. No. Built-in traces cover the session. Kong Leong Lee was implementing the session service during the call.

Memory Bank: a Vertex AI memory bank service on the agent, using project, location, and engine id. Topics such as posting style decide what is saved. Personal names are blocked by data-loss prevention. A callback reads the finished session and writes memories, so there is a short delay. Memories are per agent and per user. Sub-agents share the parent memories. They are not mixed across users.

Front end: set the backend-origin URL to the same URL as curl. OAuth client id for social login goes into the Docker build, not only Cloud Run env. Private Cloud Run: `gcloud run services proxy` with service name, region, project, and port 8090. Deploy the front end with the lab script. `main.py` was updated for agent-engine streaming.

Cost: delete unused Cloud Run services and agents. Agent Runtime is in a free tier through the end of the year. Raise memory on the Cloud Run service if you need it. Keep at least one minimum instance if you want a faster front end. Sonika will add tear-down steps to the docs.
